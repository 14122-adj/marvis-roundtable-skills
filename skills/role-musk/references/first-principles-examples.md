## 1. 三类约束的判别表

判别顺序：先问「如果所有人都改变意愿，它会不会变」→ 不会变，再看是否属于物理/数学；会变但要花资源，属于成本；会变且不需要物理理由，属于社会约定。

| 类别 | 判别问法 | 典型形态 | 违背后果 | 常见误判 |
|------|----------|----------|----------|----------|
| (a) 物理 / 数学约束 | 换掉全部人的意愿、预算、政策，它还是这样吗？ | 能量与质量守恒、光速导致的最小延迟、热力学效率上限、香农信道容量、抽样误差随样本量下降的速率、组合爆炸、支付与结算的时序不可逆 | 方案在物理上不可能，或个人可忽视的量级差距 | 把「现在做不到」当成「不可能」，忽略是工程成熟度问题 |
| (b) 资源与成本约束 | 它需要多少资金/人力/时间/产能，预算是多少？ | 单位成本、产能爬坡周期、开发人月、带宽与存储单价、现金消耗速率 | 量级上的缺口（差 3 倍可以谈，差 100 倍说明路线问题） | 把有硬预算的约束当成可无限追加；把成本问题误判为效率问题 |
| (c) 社会约定 / 行业惯例 | 谁定的？定了多久？改变它谁受损？ | 「这个岗位必须某学历」「必须走年度评审」「必须由某部门牵头」「必须用某套流程」「对外必须这样表述」 | 只是让某些人不满或打破既有权力/收益分配，不产生物理障碍 | 把惯例说成「做不到」「不合规」，用 (a) 的语言讲 (c) 的事 |

**淘汰规则**：一条约束若既拿不出物理理由，也拿不出资源预算数字，那它就是 (c)，必须进入「可谈判」清单并写明来源与既得利益方。反过来，如果一条 (b) 被反复追加预算而账算不平，要回头检查它是否其实是 (a) 的伪装（例如无视效率上限的追加投入）。

### 1.1 分类练习（先自己判，再看解析）

| 约束陈述 | 你的分类 | 解析 |
|----------|----------|------|
| 「一份合同从签署到生效至少要经过两轮法务复核」 | ? | (c)。复核轮次由组织流程决定，可由制度改变；(b) 只体现在法务人力预算上。若某类合同确实存在法定强制程序，应单独标为 (a) 式的规则约束并注明依据。 |
| 「跨洲往返通信不可能低于几十毫秒」 | ? | (a)。受光速与路由决定，任何投入都无法消除；只能通过把计算放到靠近用户一侧来规避距离。 |
| 「这个指标必须按周统计」 | ? | (c)。统计频率是管理约定；真正的约束是"决策需要多快反馈"，那才是需求。 |
| 「单机内存装不下全量数据」 | ? | (b) 为主，(a) 为辅。上限由成本与硬件决定（(b)），但"必须全量常驻内存"这一要求本身是设计选择，应拆开检验。 |
| 「培训一个熟练工至少需要 6 个月」 | ? | (b) 与 (c) 混合。学习曲线含真实的能力积累（偏 (a)/(b)），但"必须由新人从零学"是组织选择（(c)）；若可从外部获取熟练工，这条约束就松动了。 |
| 「监管要求必须留存 N 年日志」 | ? | 规则型约束，写 (a) 类但注明来源，且必须区分「监管明文要求」与「有人这么解读过」。后者是 (c)。 |

**练习要点**：分类不是目的，目的是把"不可谈判"和"可以谈"分开。若一条约束被误归为 (a)，整条推理链都会失效——这也是本手册最需要警惕的错误。

## 2. 量级估算的常用锚点

用途：在缺少精确数据时给出可信的数量级，并说明推导路径。所有锚点为教学用近似值，使用前必须核对口径与年份。

| 维度 | 常用锚点 | 口径与适用边界 |
|------|----------|----------------|
| 人力时间 | 1 人年 ≈ 1,600–2,000 有效人时 | 已扣除会议与协作开销；跨团队协作的实际产出通常再打 5–7 折 |
| 软件团队产出 | 小团队（3–7 人）在 1–2 个季度可完成一个单一职责的服务 | 前提是需求稳定、无历史包袱；遗留系统集成常使工期翻倍以上 |
| 人力成本 | 熟练工程师全成本 ≈ 薪资的 1.4–1.8 倍 | 含设备、场地、管理、招聘摊销；外包与合作方还要加协调成本 |
| 招聘与培养 | 从立项到新人独立产出通常 3–6 个月 | 领域越窄、越依赖隐性知识，周期越长 |
| 电力 | 1 kWh 用于计算的边际电费远低于设备折旧；数据中心里设备与制冷摊销常是电费的数倍 | 估算自建算力时要算全生命周期成本，不要只算电价 |
| 数据中心能效 | 成熟机房 PUE 约 1.1–1.6 | 数值越低越贵；把 PUE 当常数会低估规模扩张时的非线性成本 |
| 网络带宽 | 城域/骨干链路单位带宽成本随容量上升而下降；跨洲传输延迟受光速与路由决定 | 延迟无法靠加带宽消除；跨洲往返通常不低于数十毫秒量级 |
| 存储 | 冷存储与热存储单位成本可差一个数量级以上 | 成本差异主要来自访问模式而非介质本身 |
| 物流与交付 | 单位运输成本对「装载率」和「周转次数」敏感，对距离的敏感度低于直觉 | 与直觉相反，装载率往往比里程更能决定单位成本 |
| 流程开销 | 一次跨部门审批的等待时间常在「小时级」到「周级」 | 等待时间通常不来自工作量，而来自排队与优先级 |
| 会议成本 | 一场 10 人、1 小时的会 ≈ 10 人时 | 若同时占用高薪岗位，折算金额常高于人们预期 |
| 沟通链路 | n 人两两沟通的链路数约 n²/2 | 用于说明为什么"加人"不是线性加速；实际有效链路远少于理论值 |
| 上下文切换 | 一次任务切换的恢复开销常按 10–20 分钟量级计 | 用于估算"多线程并行"的真实成本，而非口号式批评 |
| 排队延迟 | 利用率越接近 100%，等待时间非线性上升 | 用于判断"再加一点负载"是否会引发排队崩溃；这是排队论约束，不是态度问题 |
| 数据标注 | 单位标注成本随任务难度与质检要求可差一个数量级 | 粗标与精标不可混用同一单价；估算前先定质检口径 |

**使用锚点的三步法**：① 写下你要求的量（人时 / 元 / kWh / 条 / 天）；② 从表中取最近的锚点并**说明口径差异**；③ 给出结论的误差范围（例如"在 ±3 倍内可信"）。锚点只用于把答案约束到正确数量级，绝不能代替议题自身的实测数据。

**数量级表述规范**：写「差约 1 个数量级」比写「差很多」有用；写「现实 / 下界 ≈ 20×」比写「有 20 倍空间」更诚实（前者说明口径，后者暗示承诺）。给出倍数时必须同时给出"这个倍数依赖哪个假设"。

## 3. 正反例对照：5 个抽象化工作场景

每个场景给出「错误的类比式推理」与「正确的约束式推理」。错误的推理并非荒谬，恰恰是行业里最常见的那一种。

对照时可用的判别表：

| 特征 | 类比式推理 | 约束式推理 |
|------|------------|------------|
| 起点 | 别人的做法、行业统计、标杆数据 | 物理/数学下界与资源预算 |
| 结论形态 | 「别人能，所以我们也能」 | 「下界是 X，现实是 Y，差 N 倍」 |
| 面对反例 | 追加更多案例 | 检查约束是否被误分类 |
| 面对未知 | 用类比填补空白 | 标 `unknown` 并指出缺哪个参数 |
| 失效方式 | 类比对象与本议题的关键差异被忽略 | 约束本身判断错（把惯例当物理） |

### 场景 A · 高成本硬件的降本（公开表述的概括）

- 【错误·类比式】现役同类产品的售价是 X，历史上这个行业的价格降幅每年只有百分之几，所以降本空间有限。
- 【正确·约束式】先算原材料在总成本中的占比——若物料占售价的比例只有个位数百分比，那么成本主体在制造、集成与采购层级，降价空间不在原材料价格上；再估算「原材料 + 最简装配流程」的理论下界，看现实做法离下界差几倍。若差一个数量级以上，问题在流程与组织，不在于「这个行业就是这样」。
- 检查点：BOM 占比是可查的经验事实；「行业年降幅」是过去做法的统计，不能作为未来上限的证明。

### 场景 B · 「大家默认必须做年度评审」这类惯例拆解

- 【错误·类比式】所有同类组织都做年度评审，不做会被质疑管理不透明，所以必须保留。
- 【正确·约束式】问三个问题——这个流程的原始目的是什么（信息同步 / 资源分配 / 风险拦截）？它是否由某个已消失的约束产生（例如过去没有实时数据）？把它删掉，哪个具体损失会发生？如果答案是「没有具体损失，只是有人需要一个仪式」，那它属于 (c) 类惯例；若答案是「资源分配没有别的替代机制」，那真正的约束是分配机制缺失，而不是「必须开年度会」——后者是可以换实现的。
- 检查点：替换机制的成本必须给出量级，否则删流程只是把成本藏起来。

### 场景 C · 团队规模与产出（加人能否加速）

- 【错误·类比式】项目延期 50%，同行业都是靠加人追进度，所以我们也该扩编一倍。
- 【正确·约束式】先写清任务的可并行度（有多少部分彼此无依赖）、沟通链路数与人数近似平方关系、以及新人 3–6 个月的爬坡期。再算：若可并行度低，加人只在爬坡期之后、且只在无依赖部分上产生收益；此时追加的人力成本与延期造成的损失要做量级对比。结论往往不是「加或不加」，而是「先拆依赖再加」。
- 检查点：可并行度是估算，必须写出假设；若无法估算，写 `unknown` 并指出缺哪项信息。

### 场景 D · 内部工具替换（自建 vs 采购）

- 【错误·类比式】大公司都自建平台，我们规模也不小，所以应该自建。
- 【正确·约束式】算三笔账——采购的年费（含涨价斜率）、自建的 1 人年起步成本加长期维护（通常每年占初始开发的 20%–30%）、以及「业务需求差异」是否触及供应商产品的结构性不支持项。若差异只是配置层面，自建唯一的真实收益是可控性；若差异触及核心数据模型，采购方案在任何配置下都不成立——这才是 (a)/(b) 层面的判断。
- 检查点：把「可控性」写成收益时要追问：可控性能换成什么具体能力？

### 场景 E · 研发周期压缩

- 【错误·类比式】竞品用 12 个月做完，我们要更快就得资源翻倍。
- 【正确·约束式】把周期拆成「不可压缩部分」与「可压缩部分」。不可压缩部分包括物理验证周期（材料测试、认证、临床、硬件打样与试产）与串行依赖；可压缩部分是并行组织、决策链路、返工次数。若不可压缩部分已占 70%，资源翻倍最多压掉剩余 30% 的一部分，理论下限受串行链长度决定。此时正确动作是减少串行环节（提前并行、原型前置），而不是增加人力。
- 检查点：给出的理论下限必须能追溯到串行链上的关键路径，否则只是口号。

## 4. 使用纪律

1. 本手册的所有锚点与案例都是**校准工具**，不构成本议题的证据。引用时必须换成议题自身的实际数据，或显式标注为待验证假设。
2. 类比只允许在结论形成后用于交叉校验，且必须写出失效点；本手册的反例部分同样受此约束。
3. 手册中的场景均为抽象化改写，不指向任何具体公司、人物或已发生事件；不得补充原话、时间、私人细节。
4. 估算拿不到参数时，写 `unknown` 并指出缺失项（可对应元认知的 G 编号），不要用直觉数字冒充估算。
5. 判别表的结论若与元认知标记的隐性假设冲突，以元认知的 H 编号为索引在 R2 显式回应，不得静默忽略。

### 4.1 常见自欺信号（出现即回到步骤 1 重做）

- 结论是"显然"的——真正从约束推出的结论通常带条件与倍数，不会"显然"。
- 整段推理里没有任何一个数字，或数字都来自同一段类比。
- 所有约束都被归为 (a)，因此"别无选择"。
- 反例被解释为"执行不到位"，而不是去检查约束分类是否有误。
- 推理链的某一节写着"众所周知"、"实践中必然如此"。

### 4.2 与他人协作时的两条约定

- 当同行给出的是经验规律而本手册给出的是解析下界时，两者的冲突通常是**时间尺度**问题：经验规律描述"在当前条件下会怎样"，下界描述"在最优条件下最多能怎样"。把它们放在同一层比较是错误比较，应显式写出"变量是否已被改变"。
- 当本手册的结论与议题的价值目标冲突时，不是本手册错了，而是**该议题本质上不是物理问题**。此时正确动作是声明本方法不适用，把问题交回价值判断，而不是硬凑一个约束式论证。
