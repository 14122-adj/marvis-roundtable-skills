# 决策景观

讨论关闭不等于得到结论。关闭时手上有的是一堆 claim、若干编号条目（`H`/`D`/`G`/`F`/`C`）和几笔修正记录。
本层的唯一职责是把这些**排成一张能拿去做决定的景观图**：哪些结论能用、强度多少、哪些还在争、
争的是事实还是价值、缺哪条信息可能翻转判断、谁的不同意见没有被有效反驳。

本层**不参与讨论**：不新增论据、不改立场、不替用户拍板；只做**结构聚合 + 语义复核**，且两者在输出里必须能被读者区分开。

## 定位与适用场景

- **触发**：用户问"这场讨论最后得出什么""哪些结论能用、哪些还缺信息""给我一份决策报告"；
  或 `roundtable-orchestrator` 在 `phase = closed`（或 `convergence.recommendation = close`）后调用聚合层。
- **前置**：状态文件必须已关闭，且元认知层至少运行过一次。否则先回编排层——**提前聚合等于给半成品盖章**。
- **不做**：不重开争论、不替各角色补论据、不新增任何 `H`/`D`/`G`/`F` 编号（编号只能来自元认知层）。
- **与元认知层的分工**：`meta-supervisor` 负责**发现**前提与分歧，本层负责**整理已有条目并交到决策者手里**；发现新前提、改判分歧类型要回元认知层走一遍，不在报告里下单方面结论。
- **输出形态两档**：一页纸版（只给结论与下一步）与完整版（可逐条追溯 claim id 与编号），取舍规则见 `references/output-templates.md`。

## 输入（需要的状态字段）

全部来自 `state.json`（契约 §1）。缺字段时**不要猜**：在报告中标注"该字段缺失，相关板块降级为待补"。

| 字段 | 本层用它做什么 | 缺失时的处置 |
|---|---|---|
| `claims` | claim 原文与 `basis`，供共识/少数派条目逐条溯源 | 无原文则不得生成少数派论证段 |
| `positions` | `stance_summary`、`confidence`、`compliance_drift_count`、`revision_count` | 无 `confidence` 则全部建议降为 `needs_info` |
| `revisions` | `from`/`to`/`level`/`valid`，判断修正是否有效、基线是否为修正后立场 | 修正历史缺失时不得声称"立场已演化" |
| `meta.*`（`hidden_assumptions`/`divergences`/`information_gaps`/`fallacies`） | `H`/`D`/`G`/`F` 编号条目的唯一来源：隐性假设、分歧类型与消解路径、信息缺口、待复核谬误候选 | 该板块写"元认知层未登记该类条目"，不得自造编号 |
| `meta_engagement` | 角色对注入条目的回应分布，用于判断某条 `H` 是否被回应、被谁以何种方式回应 | 缺失时 H 的"是否被回应"一栏写"无法判定" |
| `injections` | 曾强制注入的条目，用于说明哪些问题已经被逼表态 | 缺失时只描述现状，不描述过程 |
| `shared_premises` | R0 共享前提，与 `H` 对照（哪些进了元认知、哪些没有） | 缺失则前提板块只列 `H` |
| `convergence` | `recommendation`、`root_cause_reached`、`signals`，用于报告抬头的收敛状态 | 缺失时不得写任何收敛判断 |
| `argument_log` | 每轮新增关键论据计数，用于描述"讨论增量分布"（不是排名、不是质量分） | 缺失时报告不出现轮次统计 |
| `open_challenges` | 未决质疑（`C` 编号），少数派段必须写清"谁质疑了什么" | 缺失时少数派段的质疑栏写"未登记质疑" |

## 报告的六个板块

分区呈现，**不按轮次罗列发言**。每个板块都给出判据与不合格形态。

### 1. 共识区（`consensus_candidates`）

**判据**：同一条判断被 **≥2 个角色**以 `support` 或 `adopt` 明确表态（回应写进 `responses[].to`，指向该 claim id 或注入条目编号）。只有 1 个支持者、或只有"有道理""可以理解"这类未表态措辞的，不进共识区。
`strength` 三档（与 `synthesis_generator.py` 同一口径）：`unanimous`＝全部在册角色都支持；`majority`＝**有效支持数** ≥ `--min-support`；`weak`＝有效支持数低于门槛，仍列出供观察，但不计入共识。
**有效支持**的定义：明确写了 `support`／`adopt`，且该角色 `compliance_drift_count = 0`——发生从众漂移的角色，其支持不计入有效支持。
`strength` 必须被显式标注为**结构计数**（数的是表态），不是语义判定。
**不合格输出**："大家一致认为应当推进试点。"（没有支持者名单、没有强度、没有剔除漂移者）。

### 2. 分歧区（`divergence_map`）

**判据**：每条 `D` 必须写全四件事——议题、类型（事实／价值／术语／伪分歧）、各方立场（`sides`）、消解路径。
处置规则按类型分化，不能一律"继续讨论"：

- **事实分歧** → 必须挂 ≥1 个 `G` 编号（缺哪条数据、补上后可能翻转什么）；
- **价值分歧** → 显式声明不可调和，改问"在什么条件下各自的排序成立"，**不做折中表述**；
- **术语分歧** → 要求双方各给一个可操作定义，再重述主张；
- **伪分歧** → 建议撤回其中一条，并说明两条其实同义。
**不合格输出**："两种观点各有道理，建议综合考虑。"（无类型、无立场、无路径）；
或把价值分歧写成"需进一步调研后确定"。

### 3. 隐性假设清单（`hidden_assumption_list`）

**判据**：逐条列出 `H` 编号、内容、涉及角色、`challenge_effect`（若被挑战，讨论走向可能怎么变）、
`status`，以及是否已被角色回应（查 `meta_engagement`）。
"未被回应的隐性假设"必须单列——它们就是这份报告最该被继续挑战的部分。
**不合格输出**：只写"存在若干隐性假设"；把某人的疏漏写成全体默认前提；把 `status: open` 的 `H` 说成已解决。

### 4. 决策建议（`confidence_weighted_advice`）

**判据**：每条建议是可执行的下一步，措辞强度与 `confidence` 分级一致（口径见下节），
且能追溯到某个 claim id 或 `H`/`D`/`G`/`F`/`C` 编号。涉及多个角色时按**最低**自报置信度取档。
**不合格输出**："应加强沟通、持续优化。"（无来源、不可执行）；
或把某角色的原话直接搬来当建议而不标来源与置信度。

### 5. 信息缺口清单（`information_gaps`）

**判据**：每条 `G` 五要素齐全——编号、缺失信息、**补上后可能翻转的判断**、获取成本、状态。
写不出"可能翻转什么"的条目不是缺口，是好奇，不放这里。
**不合格输出**："建议补充更多数据。"（没说什么数据、翻转什么判断）；
或把不可调和的价值分歧塞进缺口清单，制造"补数据就能解决"的错觉。

### 6. 少数派观点保护（`minority_views`）

**判据**：`refuted: false` 的条目**逐条完整保留论证**：claim 原文 + 证据 + 质疑者与其质疑内容（关联 `C` 编号）。
合格的少数派段落读起来应当像一份独立主张，而不是被摘要过的一句反对意见。
**不合格输出**："另有一位成员持不同意见。"；
或为了报告对称、好看，把未被有效反驳的观点标成"已被多数意见覆盖"。

## 输出契约

字段名全部来自契约 §1（状态字段）与 §6（交接字段），本层不新增字段。`build` 默认把下列 markdown 结构输出到 stdout；`--out` 写入文件；`--json` 输出下方结构化形态。

```markdown
# 决策景观报告 — <topic>

- 会话：<session_id>　轮次：<round>/<max_rounds>　阶段：<phase>　模式：<mode>
- 收敛建议：<convergence.recommendation>　根因触及：<convergence.root_cause_reached>
- 说明：本报告为结构聚合结果；带"待复核"标记的条目为语义判断项，结论性文字均可追溯到 claim id 或 H/D/G/F/C

### 一、共识区（consensus_candidates）
| 结论 | 支持角色 | 强度 | 备注（剔除的漂移者／待复核） |
|---|---|---|---|
| ……（来源：M1-1, G2-1） | musk, munger | weak | 结构计数，非语义判定；某角色 compliance_drift ≥1，支持未计入 |
无候选时写：本场讨论未产生满足 --min-support 的共识候选。

### 二、分歧区（divergence_map）
#### [D1] 议题　类型：事实｜价值｜术语｜伪分歧
- 各方立场：……
- 消解路径：……
- 关联信息缺口：G1（事实分歧必须给出 G 编号）
- 状态：open｜answered｜dropped

### 三、隐性假设清单（hidden_assumption_list）
- [H1] 内容：……　涉及角色：……　若被挑战可能改变：……
- 状态：open　是否已被回应：是（回应方式与来源见 meta_engagement）／否（单列）

### 四、决策建议（confidence_weighted_advice）
#### 高置信度（high）　#### 中等（medium）　#### 需补充信息（needs_info）
每条格式：建议内容（来源：claim id 或编号；依据角色自报 confidence）

### 五、信息缺口清单（information_gaps）
| 编号 | 缺失信息 | 补上后可能翻转的判断 | 获取成本 | 状态 |
|---|---|---|---|---|

### 六、少数派观点保护（minority_views）
#### [角色] claim id：claim 原文
- 证据：……
- 收到的质疑：C1（质疑者=……）：……
- 状态：refuted=false —— 未被有效反驳，完整保留
```

上列模板中的板块标题在本文件内降一级书写，以免与本 SKILL.md 的章节层级混淆；`build` 实际渲染时六个板块是报告标题（H1）下的一级小节（`## 一、共识区（候选，需复核）` 起），并在末尾附一节"未被检验的主张"作为附录（`argument_log` 与 `responses_received` 为空的主张）。结构一致，只有标题层级不同。

结构化形态（与编排层交接块同源，可直接被下游消费）：

```jsonc
{
  "session_id": "rt-20260601-101500-a1b2",   // 以下 6 项取自契约 §1
  "topic": "议题原文",
  "round": 2,
  "max_rounds": 3,
  "phase": "closed",
  "convergence": {"rounds_without_new_argument": 1, "root_cause_reached": false,
                  "recommendation": "close", "signals": []},
  "consensus_candidates": [{"text": "……", "supporters": ["musk", "munger"], "strength": "weak"}],
  "divergence_map": ["D1", "D2"],
  "hidden_assumption_list": ["H1", "H2"],
  "information_gaps": ["G1"],
  "minority_views": [{"role": "pg", "claim_id": "P1-1", "text": "……", "refuted": false}],
  "confidence_weighted_advice": [{"text": "……", "confidence": "needs_info"}],
  "needs_judgment": true                     // 契约 §7：语义判断项交由模型或人工复核
}
```

## 工作流

1. **读状态**：确认 `phase = closed` 或 `convergence.recommendation = close`，且元认知层已运行。不满足就停在这里，回到编排层，不要产出一份"讨论进行中"的决策报告。
2. **build**：
   ```bash
   python scripts/synthesis_generator.py build --state S [--out REPORT.md] [--json] [--min-support 2]
   python scripts/synthesis_generator.py check --state S
   python scripts/synthesis_generator.py selftest
   ```
   `build` 默认 markdown 到 stdout（给 `--out` 则写文件），`--json` 输出结构化形态；`--min-support` 是共识所需的最小支持人数（默认 2，抬高它只会让共识区更保守，不会制造共识）。
3. **复核 `needs_judgment` 项**：脚本只做结构聚合——计数、挂链、找缺口。以下三类必须由模型或人逐项复核：共识强度是否被高估、`D` 的类型是否判错、`H` 的 `challenge_effect` 是否属实；复核结论写进对应条目的备注，**不要直接改脚本给出的计数**。
4. **check**：读完整性检查结果（`minority_preserved` / `weak_consensus` / `drift_warnings` / `gaps_missing_for_fact_divergence` / `needs_judgment`）。凡是报错项，要么补上，要么在报告里写明为什么补不上。
5. **交付**：按读者选一页纸版或完整版；结尾保留边界声明——本层不做语义判定、不保证跳出底座模型自身的偏见、也不声称讨论"已触达根本"。

## 完整性检查

四项，`check` 会给出结构信号，最终判定仍需复核：

1. **少数派是否被保留**：`minority_views` 中 `refuted: false` 的条目是否逐条出现在报告第六板块，且带 claim 原文、证据、质疑者与质疑内容。缺失即为不合格。
2. **共识强度是否被高估**：剔除 `compliance_drift_count ≥ 1` 的角色后，有效支持数是否仍 ≥ `--min-support`；不满足则降档（`majority` → `weak`）或移出共识区。**宁可没有共识，不要弱化判据**。
3. **是否存在系统性从众漂移**：统计发生漂移的角色数。1–2 个 → 在共识区备注其支持不计入；**≥3 个 → 报告必须显式写出"当前共识可能是假共识"**，并说明漂移发生在哪个议题上。这是本层最重要的一条自检。
4. **事实分歧是否都配了信息缺口**：每个 `type = fact` 的 `D` 都要挂上 `G`；挂不上的，要写明"该分歧当前无法靠补信息解决，需回到元认知层重新分类"，而不是留空。

## 置信度分级口径

| 档位 | 区间 | 措辞纪律 |
|---|---|---|
| `high` | `confidence ≥ 70` | 可写"建议优先执行" |
| `medium` | `40 ≤ confidence ≤ 69` | 必须带限定条件（"在 X 成立的前提下"） |
| `needs_info` | `confidence < 40` | 只能写"待补充信息后再判断"，不得写成结论 |

- 取值来源是 `positions[role].confidence`，即**角色自报**（0–100 整数），不是系统测量值，也不是概率。
  因此报告中**禁止**出现"该结论有 70% 的可能成立"这类表述；它只用于排序与措辞强度。
- 一条建议涉及多个角色时取**最低**值（保守原则）。
- 角色若发生 `valid: true` 的有效修正，按修正后基线的 `confidence` 取值；`valid: false`（从众漂移）不改变基线，也不抬高置信度。
- 建议若依赖尚未闭环的 `G` 编号，无论自报置信度多高，一律降为 `needs_info`。

## 反模式

1. ❌ 为了报告对称好看而伪造或强化共识：没有 ≥2 个明确表态，就不许出现共识条目。
2. ❌ 把 `refuted: false` 的少数派观点压成一句"另有不同意见"，或为版面删掉它。
3. ❌ 按轮次罗列发言（"第一轮某人说……第二轮某人说……"）——本层按结论类型分区，不按时间线。
4. ❌ 断言未执行的动作：写"已达成共识""已验证""已挖到根本"。只能写"候选""需复核""若补上 X 则判断可能改变"。
5. ❌ 把价值分歧写成待调研事项，或把事实分歧写成不可调和。两种都是偷懒，方向相反。
6. ❌ 直接搬运角色原话当决策建议，不标来源编号与置信度档位。
7. ❌ 把 `check` 通过当成语义结论。脚本报的是结构一致性，不是"这份报告是对的"。
8. ❌ 讨论未关闭就提前聚合，或在报告里自行重启争论、替角色补论据。
9. ❌ 用多个角色的 `confidence` 做加权平均，算出一个人造的"总体置信度"。
