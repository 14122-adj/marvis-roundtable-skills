# 战术指挥部手册（V4）

`ultimate-roundtable` V4.1 的操作手册。回答四个问题：
**北极星怎么定、分舱镜头怎么调、死锁怎么判、战术清单怎样才算"能落地"。**

## 1. 北极星指标的选取

北极星是**全场唯一的焦点**。所有发言必须围绕它，否则视为无效。

### 合格的北极星

| 判据 | 说明 |
|---|---|
| **单一** | 一个指标，不是一个指标组（❌"月活与利润率"） |
| **可测** | 能给出数字与口径（✅"30 日月活"，❌"用户满意度"） |
| **有方向** | 知道涨好还是跌好（❌"流失率与留存率"二选一即可，别同时） |
| **有时间窗** | 隐含或显式的时间范围（✅"本季度月活"） |
| **可归因** | 讨论的动作能影响它（❌"行业增速"——讨论改不了） |

### 常见误选

- ❌ **把 KPI 当北极星**：北极星是决策焦点，不是考核项；
- ❌ **选一个谁都无法影响的指标**：讨论会变成"分析形势"而不是"做决定"；
- ❌ **同时要两个**：V4 强制单一，多指标会导致三选一无法裁决；
- ❌ **选得太窄**：比如"本季度月活"，会导致所有长期方案被判为无效。

**一句话检验**：如果三个方案 A/B/C 都能用这个指标排序，它就是合格的北极星。

## 2. 分舱镜头调参

六个镜头定义在 `attention_split.py` 的 `LENSES` 里，每个镜头是一组关键词。
分舱时按关键词字面匹配决定"这条历史你看不看得见"。

### 三条铁律

1. **北极星相关条目对所有角色可见**——否则角色会忘了为什么开会；
2. **强制条目（`must_respond` / `must_resolve`）永不屏蔽**——否则元认知注入失效；
3. **只记录 id，不复制内容**——分舱不改写任何原文，`muted` 里只有 id。

### 什么时候该调

| 现象 | 原因 | 调整 |
|---|---|---|
| `visible_ratio = 1.0` | 历史太少或关键词太宽 | 收紧关键词，或等更多历史 |
| `visible = []` | 镜头与议题不匹配 | 加议题领域的词（如"合规""供应链"） |
| 某角色总看不见关键质疑 | 镜头过窄 | 给该角色加 `must_respond` 强制可见 |
| 分舱后讨论明显变浅 | 屏蔽过多 | 提高可见比例（减少关键词或加白名单） |

**不要为了"看起来分舱生效"而人为屏蔽关键信息**——分舱的目的是减噪，不是制造信息茧房。
被屏蔽的内容在报告里是可追溯的（`muted` 清单），必要时可以人工复核。

## 3. 死锁判定细则（V4.1 双路径）

### 3.1 语义路径（主）

主持人**每轮结束在内心完成判定**（不输出过程），对比红蓝双方本轮与上一轮的发言，
逐对给出三标签之一：

| 标签 | 判据 | 动作 |
|---|---|---|
| `[REPEAT]` | 只是换了说法、同义词替换、举了不同例子；**核心论点、支撑数据、推导逻辑**完全没变 | 计为复读 |
| `[PROGRESS]` | 提出新证据、新前提、修正观点、针对性反驳对方**特定词句** | **放行**（本轮有推进） |
| `[PROGRESS]` | 反问、质疑、要求提供数据 | **放行**（同上） |
| `[UNCERTAIN]` | 无法确定 | 不作判断，交给结构路径兜底 |

**汇总规则**（`round_semantic_summary`）：

```
本轮 judged == 0            → semantic_repeat = None（未判，走结构路径）
本轮 PROGRESS > 0           → semantic_repeat = False（放行，哪怕相似度很高）
本轮 REPEAT > 0 且无 PROGRESS → semantic_repeat = True（复读）
本轮全是 UNCERTAIN          → semantic_repeat = None（走结构路径）
```

**熔断**：`semantic_repeat = True` → **本轮即刻熔断**（不需要连续两轮）。

> spec 原文是「一旦发现语义复读（**或者**连续两轮没有产生新事实）」——
> 这是两个**独立**的触发条件，门槛不同：
> 语义复读是「一旦发现」→ 单轮即熔断；
> 结构兜底才是「连续两轮」。

### 3.2 结构路径（兜底）

无语义判定时，**连续两轮**同时满足四项：

| 判据 | 阈值 | 说明 |
|---|---|---|
| 复读 | 与上一轮最大相似度 ≥ 0.55 | 字符二元组 Jaccard，只抓逐字重复 |
| 无新事实 | `new_arguments = 0` 且 `new_tool_results = 0` | 没有新论据也没有新查证 |
| 立场未动 | `valid_revisions = 0` | 没有任何有效修正 |
| 靶点未变 | 攻击的 claim 集合与上一轮相同 | 还在打同一批靶子 |

### 3.3 判定边界

- **语义优先于结构**：语义判 `PROGRESS` 时，即使相似度 1.0 也放行
  （新证据完全可能用相似措辞表达）；
- **首轮交锋没有"上一轮"可比**：结构路径改判"本轮是否毫无新意"；
- **靶点变了就不算死锁**：说明双方在扩大战线，还在推进；
- **有新工具结果就不算死锁**：哪怕结论没变，信息是新的；
- **`UNCERTAIN` 不等于放行**：它只是"不作判断"，最终由结构路径决定。

### 3.4 为什么需要语义路径

实测：两段意思完全相同的话，换个说法后字符相似度可能只有 **0.0x**——
结构路径完全抓不到。而如果"我觉得他们在重复"不落成一条带理由的记录，
它就只是主持人的主观感觉，事后无法复核。

所以 `semantic_verdicts` 的每条记录都必须带 `reason`：

```json
{"round": 3, "from": "munger", "to": "munger", "label": "REPEAT",
 "reason": "换了说法，核心论点仍是切换成本被低估"}
```

### 3.5 熔断之后

```
[系统强制熔断] 双方已陷入实质重复，此议题直接交由最终裁决阶段处理。
```

1. `debate_closed = true`，后续任何 stage2 提交一律拒绝（退出码 3）；
2. 议题移交阶段三，直接进入三选一投票；
3. 熔断记录写入报告「过程留痕」，包含**触发路径**（semantic / structural）、
   连续停滞轮数与具体理由。

**熔断不是失败**：它承认"这两个立场无法通过辩论收敛"，把决策权交还给主持人。
继续辩下去只会消耗轮次，不会产生新信息。

## 4. 三选一方案的互斥性设计

三个方案必须**互斥**：不是同一个方案的三个版本，而是三条不同的路。

### 设计模板

| | 方案 A（激进） | 方案 B（保守） | 方案 C（降维） |
|---|---|---|---|
| 风险 | 高 | 低 | 中（但是全新的风险类型） |
| 收益 | 高 | 低 | 可能很高 |
| 前提 | 需要 X 成立 | 几乎不需要前提 | 需要跳出当前约束 |
| 失败方式 | 一次性崩 | 慢慢落后 | 想错了方向 |

### 合格样例（评审议题）

- **A 激进**：全量改为季度评审，三个月内切换完毕
- **B 保守**：维持年度评审，只把材料准备流程精简一半
- **C 降维**：取消固定评审，改为触发式评审——指标跌破阈值才开

三个方案在"评审频率"这个维度上分别是**提高 / 不变 / 取消**，互斥且都可行。

### 不合格样例

- ❌ A："三个月内切换"；B："半年内切换"；C："一年内切换"
  —— 只是时间不同，本质是同一个方案；
- ❌ A："激进推进"；B："稳步推进"；C："谨慎推进"
  —— 形容词换皮，脚本会判为描述重复；
- ❌ C 写成"A+B 的组合"
  —— 那不是第三个方案，是回避选择。

### 互斥性检验

脚本用的是**描述文本完全相同**检测。更严格的语义互斥需要人判断，
但下面这个自检能抓出大部分换皮：

> 把三个方案的 summary 并排念一遍，如果听众需要问"这两个有什么区别"，
> 就说明它们不够互斥。

## 5. 战术清单的颗粒度标准

四要素：**负责人 / Start / KPI / Kill**，外加 Need Info。

### 负责人（owner）

- ✅ 必须是六个角色之一（或明确标注的召唤角色）；
- ✅ 一个方案一个主负责人，不要"XX 和 YY 共同负责"；
- ❌ "团队"、"大家"、"相关同事"——没有主语就没有责任人。

### 第一步（start）

- ✅ 有动作、有对象、有时间："本周在 2 个团队上线触发式评审"；
- ❌ "开始推进"、"启动项目"——没有可执行的第一个动作。

### 关键指标（KPI）

- ✅ **必须含数字**："30 天内触发 5 次以内，月活不低于 9%"；
- ✅ 有观察窗口（30 天）、有阈值（5 次 / 9%）；
- ❌ "提升用户满意度"、"优化流程效率"——没有数字，无法判定成败；
- ❌ "大概提升 10%"——含"大概"，直接拒绝。

### 止损红线（Kill）

- ✅ **必须含数字**："如果 30 天内触发超过 12 次，立刻停止并回滚到年度评审"；
- ✅ 写清停止后做什么（回滚 / 转方案 B）；
- ❌ "如果效果不好就停止"——"不好"不是判据；
- ❌ "视情况调整"——咨询体，直接拒绝。

### 补充调研（Need Info）

- ✅ 至少一条，且写清"知道它会改变什么判断"；
- ❌ 空列表——V4 认为没有未知项是可疑的，通常意味着调研不足。

## 6. 常见坏方案与坏清单

| 坏产出 | 为什么坏 | 怎么改 |
|---|---|---|
| "建议进一步调研后再决定" | 咨询体，等于没决定 | 给出 A/B/C 并拍板一个 |
| "三个方面都要兼顾" | 和稀泥 | 三选一，说清放弃什么 |
| "由产品团队负责推进" | 无主语 | 指定到具体角色 |
| "预期效果良好" | 无数字 | 给 KPI 与观察窗口 |
| "风险可控" | 无判据 | 给 Kill 阈值 |
| "如果顺利的话…" | 假设性表述 | 删掉，只写确定动作 |
| 三个方案都叫"优化方案" | 不互斥 | 重设计成三条不同的路 |

## 7. 一个完整的 V4 走查示例

**议题**：要不要把年度评审改成季度评审
**北极星**：月活

| 阶段 | 发生了什么 | 产出 |
|---|---|---|
| 零 | 加载 1 条历史记忆，锚定北极星"月活" | 开场白 + 焦点规则 |
| 一 | 六人各 ≤150 字交底，每条带 `[数据诉求]`+`[Tool Call]`+表态；同时生成 6 份分舱声明 | 6 条数据诉求、分舱可见比例 0.17 |
| 二 | 3v3 对抗，1 次打断 + 1 次验真；语义判定为 `REPEAT` → **即刻触发熔断** | `[系统强制熔断]` + 发言权切断 |
| 三 | 直接进入三选一：A 全量季度化 / B 只精简材料 / C 触发式评审 | C 得 3 票，拍板 C |
| 四 | 战术清单：karpathy 负责，本周上线，KPI 与 Kill 都带数字 | 可执行指令 |
| 报告 | 五节 V4 报告 | 含北极星、裁决、战术清单、记忆 |

**关键观察**：这场讨论在阶段二就被熔断了，但产出质量反而更高——
因为熔断把剩下的轮次留给了"做决定"，而不是"继续吵"。
这正是 V4 与 V3 最大的区别：**V4 关心的是停下来之后能干什么。**
