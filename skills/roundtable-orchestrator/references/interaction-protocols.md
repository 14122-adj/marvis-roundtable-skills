# 交互协议细则

本文件是 `roundtable-orchestrator` 的参考手册，用于回答"这一轮该怎么组织发言"。
原则一句话：**规定目标，不规定形式**。

## 目录

1. 两种交互模式
2. 隔离发言的工程做法（防锚定）

5. 轮次切换判定

## 1. 两种交互模式

| 模式 | 含义 | 适用 | 硬约束 |
|---|---|---|---|
| `parallel_isolated` | 所有角色**互相看不见**本轮其他人的发言，同时独立产出 | 第 1 轮立论；重新开一个新议题时 | 唯一保留的形式约束 |
| `cross_exam` | 自由交叉：角色自主选择追问谁、追问几人、或只补自己的证据 | 第 2 轮起的深挖与综合 | 无配对、无人数下限 |

**为什么只保留一个硬约束**：如果先让甲说完，乙丙丁戊己都会不自觉地进入甲的概念框架，
讨论会退化成"对甲的方案做修补"。隔离一轮，代价是多花一次生成，收益是拿到六个真正独立的视角。

**被废除的约束**（原方案有、本版本明确删除）：

- 「本轮必须一对一轮流」→ 换成"自行选择追问对象"；
- 「本轮必须联动 ≥2 人」→ 换成"建议优先处理未被检验的论断"；
- 「每段不得超过 N 字」→ 换成"发言密度靠论据数量衡量，不靠字数"。

形式约束之所以有害：它让角色把注意力放在**满足形式**（找个人来质疑）而不是**推进认知**（找到真正的缺口）。

## 2. 隔离发言的工程做法（防锚定）

在单次对话里模拟隔离，有三种可行做法，按可靠性从高到低：

1. **分别调用**（最可靠）：六个角色各自单独对话，禁止携带其他角色的文本，最后统一登记。
2. **分批生成但物理隔离**：一次只给一个角色的指令，同一批里不出现其他人的发言内容。
3. **单次生成但强制标注**（最弱）：在提示里明确"不要引用任何其他人的观点，只写你自己的判断"，
   并在登记时检查是否出现"正如某某所说""同意上述观点"——出现即判定为隔离失效，重新生成该角色发言。

**隔离失效的判据**（出现任一即失效）：

- 发言里出现其他角色名；
- 出现了本该在别处出现的 claim id（如马斯克的发言引用 `P1-2`）；
- 六个角色的用词、结构高度雷同（相似度检查：任两条 claim 相似度 ≥0.7 的比例超过 30%）。

> 隔离失效不致命，但要**在记录里标注**"本轮实际未隔离"，不能假装做过。

## 3. 自由交叉的追问策略

第 2 轮起不给角色配对，但给**建议清单**。清单出来源是 `round_controller.py plan` 的 `advisory`：

| 建议项 | 含义 | 交给角色时的话术 |
|---|---|---|
| `prioritize_untested_claims` | 从未被任何人回应的论断 | "这些论断还没有被检验过，建议你挑最相关的去检查它的前提或证据" |
| `unanswered_challenges` | 上一轮提出的质疑还没有人回答 | "有一条针对你的质疑还没有回应，建议正面回答或明确说明为什么不接受" |
| `must_respond` | 元认知注入的隐性假设 | **强制**：本轮至少正面回应其中一条 |

角色自主决策的三种合法形态：

1. **追问一个人**（正常情况，深度优先）；
2. **同时追问多人**（当多条论断共享同一个可疑前提时，效率更高）；
3. **不追问任何人**，只补自己的证据、或撤回自己的一条断言（这是完全合法的——没有新证据时硬找一个人来吵架是浪费轮次）。

**追问质量的判据**（用于元认知层评估，不用于限制角色）：

- 追问的是**前提、证据、边界条件**之一，而不是"你错了"；
- 引用了对方原文或 claim id；
- 说清了"如果你能给出 X，我就接受"——即给出可以终结争论的条件。

## 4. 覆盖度诊断

`round_controller.py coverage` 输出**结构计数**，不是质量评价：

```
untested_claims     从未被任何人回应的论断 → 讨论可能只覆盖了最响亮的几个人
open_challenges     悬空质疑 → 上一轮提了问题，没人接
response_attention  每条论断被回应的次数分布 → 检查是否所有人都在回应同一个人（被带节奏）
per_role[*].claims  各角色产出量 → 有人 0 条说明这个视角本轮缺席
```

三个常见病征与处置：

| 病征 | 含义 | 处置 |
|---|---|---|
| 一个角色的论断被回应 5 次、其余为 0 | 讨论被单人框架绑架 | 元认知层点名，下一轮 `must_respond` 指向其他人的论断 |
| 某角色 claims = 0 但发言很长 | 只评论不产出（"评论家"角色） | 要求该角色至少给出一条可被证伪的 claim |
| `untested_total` 连续两轮不降 | 大家都在回应同一批老论断 | 换问题：把注入的 `forbidden` 设成"继续争论 X" |

## 5. 轮次切换判定

```
R0 → R1     总是
R1 → meta_1 总是（不可跳过）
meta_1 → R2 若 must_respond 非空；若元认知判定全部为伪分歧 → 直接收敛
R2 → meta_2 总是
meta_2 → R3 若 convergence=continue|deepen
meta_2 → 关闭 若 convergence=close，或主要分歧都是价值分歧（再辩无增量）
R3 → 关闭    总是（除非用户要求加轮）
```

**加轮规则**：用户要求超过 3 轮时，可以继续，但每加一轮都要回答"这一轮要解决的**新**问题是什么"。
答不出来就说明该收敛了——加轮不能只是让讨论更久。

## 6. 三个完整流程示例

### 例 A：工程方案选型（3 轮，rigorous）

- **R0**：议题"自建 vs 采购"，成功判据"三年总成本与交付风险"。共享前提登记：*"必须自研核心能力"*（往往没人论证过）。
- **R1 隔离**：马斯克给下界估算；Karpathy 拆模块与接口假设；芒格做失败路径倒推；乔布斯砍功能；费曼要求术语可操作化；pg 要案例。
- **meta_1**：抓出隐性假设 H1="自研核心能力"，分类 D1=价值分歧（自研是价值偏好还是成本判断），信息缺口 G1="三年运维人力成本"。
- **R2 交叉**：Karpathy 追问马斯克的下界估算忽略了运维；pg 用案例反驳"自研一定更好"；马斯克回应 H1——**承认 H1 是价值前提而非事实**（一次 local 修正）。
- **meta_2**：新增论据从 5 条降到 1 条 → `deepen`；登记 G1 未补，建议收敛。
- **R3**：给出"若补上运维数据则倾向采购"的条件式结论，并保留 pg 的少数派论证。

### 例 B：价值争议（提前收敛）

议题"要不要为了增长牺牲体验"。meta_1 判定主要分歧为**价值分歧**（双方对"什么算好产品"排序不同），
meta_2 检测到重复表述 → `close`。正确产出不是"折中方案"，而是"这是价值排序之争，不是事实之争；
在 X 条件下增长优先，在 Y 条件下体验优先"。

### 例 C：用户中途给了新事实（`--allow-uncited`）

讨论进行到 R2，用户提供了一份实测数据。此时：

1. 由元认知层把新数据登记为信息缺口 `G` 的补充（或直接登记为一条 `empirical` claim）；
2. 角色据此修正时，`trigger` 引用该 `G` 编号即可——**不需要** `--allow-uncited`；
3. 只有当用户给的是一个系统里没有编号的新事实、且来不及登记时才用 `--allow-uncited`，
   并在 `trigger` 里写清"用户于本轮提供的实测数据"。

## 7. 常见错误对照表

| 错误做法 | 后果 | 正确做法 |
|---|---|---|
| 六人各说一遍，没人回应任何人 | 六份独立报告，不是讨论 | R2 起强制回应注入项 + 建议清单 |
| 硬指派"你去质疑他" | 质疑变成表演，为质疑而质疑 | 给建议清单，让角色自选 |
| 跳过元认知直接进 R2 | 表层循环，挖不到前提 | meta 轮不可跳过，脚本会报阻塞 |
| 每轮都加人/加轮 | 稀释，越讨论越散 | 加轮必须回答"新问题是什么" |
| 把 `must_respond` 列成 8 条 | 角色挑最软的回应，等于没强制 | 1–3 条 |
| 用字数控制发言长度 | 压制论据密度，鼓励修辞 | 用论据条数与 basis 类型衡量 |
| 讨论完直接写"达成共识" | 掩盖未解决的前提与少数派 | 输出共识候选 + 分歧类型 + 未反驳的少数派 |
